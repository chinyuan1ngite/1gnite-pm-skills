# 某政务项目产品工作流（脱敏示例）

本目录展示一个真实项目形态的 AI 产品协作资料库如何组织，而不是只给出一段通用提示词。示例保留了以下工作特征：

- 以 `AGENTS.md` 统一约束事实、推断、建议、待确认和历史资料的边界；
- 从会议记录提取需求来源，贯穿 PRD、HTML 原型、字段字典、按钮表、权限矩阵、状态流转和测试用例；
- 使用稳定中文编号建立跨文档引用；
- 支持从现有页面反向补档，但不把页面现状直接当成最终需求；
- 将正常、空态、异常、无权限、提交中和失败恢复纳入原型与验收；
- 通过“不做范围”和“待确认问题”控制模型补造业务规则。

## 示例链路

从“单位管理”案例可以顺着编号追溯一条完整链路。

1. 从[模拟会议记录](01_原始资料/会议纪要/单位管理_模拟会议记录.md)整理[会议纪要](01_原始资料/会议纪要/单位管理_会议纪要.md)，提取确认结论、待确认事项和不做范围。
2. 结合[项目口径库](00_项目口径库)更新[单位管理 PRD](03_PRD/PRD_单位管理.md)。
3. 下载示例后用浏览器打开[单位管理原型](04_HTML原型/政务管理端/权限管理_单位管理.html)，对照[结构化台账](02_结构化台账)查看页面、字段、按钮、权限和状态。
4. 把验收标准展开为[功能测试用例](07_测试验收/功能测试点.csv)，用合成数据记录前置条件、步骤和预期结果。8 条用例均为设计示例，执行状态为「未执行」。

所有组织名称、环境地址、人员、联系方式、证件号码和业务数据均已替换为通用名称、保留域名或明显的掩码示例。这里的业务内容只用于展示工作流结构，不代表任何真实政务系统。

## 使用方式

让 Agent 按[工作流指南](工作流指南.md)整理会议输入或设计测试用例。

将本目录复制为新项目骨架，先补齐 `00_项目口径库` 中的项目事实，再让 agent 按 `AGENTS.md` 工作。不要直接把示例字段、角色、状态或流程当成新项目需求。
