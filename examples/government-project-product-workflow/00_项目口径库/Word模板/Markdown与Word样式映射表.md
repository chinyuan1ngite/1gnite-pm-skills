# Markdown 与 Word 样式映射表

## 0. 使用说明

本文档定义某政务项目 Markdown PRD 转换为 `.docx` 时的结构映射。排版数值以 `Word排版规范.md` 为准，内容结构以 `PRD结构模板.md` 为准。脱敏示例不附带原项目二进制模板；实际使用时请采用团队自行创建的干净模板。

转换原则：

1. Markdown 是内容主版本，Word 是排版交付版本。
2. 通过语义结构选择 Word 样式，不根据 Markdown 的视觉外观猜测样式。
3. 标题、列表、表格和图题必须生成真实 Word 结构，不能只做直接格式。
4. 方括号占位符在正式交付前必须替换、删除或明确标注为待确认。
5. `功能-001` 等稳定编号保持原文，不参与 Word 章节自动编号。

## 1. 封面元数据映射

建议在 Markdown 文件头部或生成指令中提供以下元数据：

```yaml
项目全称: "[项目全称]"
文档类型: "产品需求说明书"
系统名称: "[系统名称]"
功能模块: "[功能模块]"
责任人: "[责任人]"
编制日期: "[YYYY-MM-DD]"
编制单位: "[编制单位]"
文档版本: "V0.1"
```

| Markdown/元数据 | Word 位置 | Word 样式 | 转换规则 |
| --- | --- | --- | --- |
| `项目全称` | 封面顶部 | `PRD Cover Project Title` | 允许自动换行，最多建议三行 |
| `文档类型` | 项目全称下方 | `PRD Cover Document Type` | 默认“产品需求说明书” |
| `系统名称` | 封面元数据 | `PRD Cover Metadata` | 标签右对齐、取值左对齐 |
| `功能模块` | 封面元数据 | `PRD Cover Metadata` | 不从文件名自动编造 |
| `责任人` | 封面元数据 | `PRD Cover Metadata` | 无确认来源时保留待确认 |
| `编制日期` | 封面元数据 | `PRD Cover Metadata` | 使用 `YYYY-MM-DD` |
| `编制单位` | 封面底部 | `PRD Cover Organization` | 无确认来源时不得沿用历史单位 |
| 修订记录 | 第二页表格 | 修订记录表格样式 | 一次修订一行 |

## 2. 正文结构映射

| Markdown 结构 | 示例 | Word 结构/样式 | 转换规则 |
| --- | --- | --- | --- |
| 一级标题 | `# 文档标题` | 不直接进入正文 | 文档最外层标题用于封面或文件元数据；正文从二级 Markdown 标题映射时需按项目约定统一降级 |
| 主章节 | `## 文档说明` | `Heading 1` | Word 自动显示 `1. 文档说明`，Markdown 中不要手工加数字 |
| 二级章节 | `### 适用范围` | `Heading 2` | Word 自动显示 `1.1. 适用范围` |
| 三级章节 | `#### 功能名称` | `Heading 3` | Word 自动显示 `1.1.1. 功能名称` |
| 四级及以下标题 | `##### 处理规则` | `PRD Label` | 不进入自动章节编号；原则上避免超过三级 |
| 普通段落 | 连续文本 | `Normal` | 宋体 12 磅，首行缩进 2 个汉字 |
| 强调标签 | `**功能说明：**` | `PRD Label` | 标签单独成段时映射为标签样式 |
| 行内加粗 | `**关键内容**` | 同段落样式的加粗 run | 不改变段落样式 |
| 行内斜体 | `*说明*` | 同段落样式的斜体 run | 谨慎使用，不用于业务状态 |
| 说明/提示 | `> 提示内容` | `PRD Note` | 只承载编写提示、限制或注意事项 |
| 分隔线 | `---` | 段落分隔或分页规则 | 不默认生成装饰线；按上下文决定 |
| 显式分页 | `<!-- PAGE_BREAK -->` | Word 分页符 | 不用连续空段落模拟分页 |
| 显式分节 | `<!-- SECTION_BREAK -->` | Word 新页分节符 | 仅用于横向表格或特殊页面设置 |

### 2.1 标题层级约定

某政务项目 PRD Markdown 通常以 `# PRD_【模块名称】` 作为文档标题。转换时推荐：

- Markdown `#` → 封面项目/文档标题，不进入自动章节编号；
- Markdown `##` → Word `Heading 1`；
- Markdown `###` → Word `Heading 2`；
- Markdown `####` → Word `Heading 3`；
- Markdown `#####` 及以下 → Word `PRD Label` 或普通加粗段落。

若 Markdown 本身从 `#` 开始承载正文主章节，转换器必须统一采用另一套映射，不能在同一文档中混用两种层级规则。

## 3. 列表映射

| Markdown | Word 结构 | 转换规则 |
| --- | --- | --- |
| `- 列表项` | `List Bullet` | 使用真实项目符号定义，不保留文本中的 `-` |
| `1. 步骤` | `List Number` | 使用真实有序列表，不把数字作为正文字符 |
| 嵌套列表 | 多级 Word 列表 | 原则上不超过三级，缩进和悬挂保持一致 |
| `- [ ] 检查项` | 复选框字符＋列表段落 | 使用 `☐` 或内容控件前需确认交付环境兼容性 |
| `- [x] 已完成` | 复选框字符＋列表段落 | 使用 `☒`，不得用图片模拟小图标 |

转换时禁止使用 Symbol 私有字符作为项目符号。项目符号必须在 Word、LibreOffice 和 PDF 中均可正常显示。

## 4. 表格映射

### 4.1 基础映射

| Markdown | Word | 转换规则 |
| --- | --- | --- |
| 表头行 | Word 表格首行 | 灰底、加粗、居中、重复表头 |
| 分隔行 `| --- |` | 不生成内容行 | 仅用于识别 Markdown 对齐方式 |
| 普通数据行 | Word 表格正文行 | 宋体 10.5 磅、允许自动增高 |
| 左对齐列 | 单元格左对齐 | 用于名称、描述、规则、异常和验收 |
| 居中列 | 单元格居中 | 用于编号、状态、是否、日期和版本 |
| Markdown 换行 `<br>` | 单元格内换行 | 仅在同一字段存在真实分项时使用 |

### 4.2 列宽算法

1. 计算正文可用总宽度 8,690 twips。
2. 识别短值列、名称列和描述列。
3. 短值列分配 10%–18%，描述列优先分配剩余宽度。
4. 所有列宽之和必须等于表格宽度。
5. 同时写入 `tblW`、`tblGrid` 和每个单元格 `tcW`，不得依赖自动适应窗口。
6. 表格跨页时重复首行，不设置固定行高。

### 4.3 复杂表格

- Markdown 不支持的合并单元格应通过结构化数据或专门转换规则生成。
- 包含长段落的复杂矩阵应评估是否拆分为多张表或正文小节。
- 横向表格需要独立横向分节，表后恢复纵向并检查页眉页脚继承关系。
- CSV 台账导入 Word 时，必须保持表头、编号和字段语义，不因排版改名。

## 5. 图片、Mermaid 和图题映射

| Markdown | Word | 转换规则 |
| --- | --- | --- |
| `![说明](path)` | 居中嵌入型图片 | 保持宽高比，最大宽度约 6 英寸 |
| 图片后的斜体说明 | `PRD Caption` | 转换为“图 N  图名” |
| Mermaid 代码块 | 渲染后的 PNG/SVG＋图题 | 源码保留在 Markdown，Word 插入清晰渲染结果 |
| HTML 原型链接 | 超链接或附件清单 | 不把本地临时路径作为正式链接 |
| 页面截图 | 嵌入型图片 | 清理临时批注和敏感信息 |

图片不能替代文字规则。流程、状态、权限和异常仍需在正文或表格中完整表达。

## 6. 代码、接口和特殊内容

| Markdown 结构 | Word 映射 | 说明 |
| --- | --- | --- |
| 行内代码 `` `字段名` `` | 等宽字体行内 run | 建议 Consolas 10.5 磅 |
| 围栏代码块 | 等宽字体段落或单列表格 | 保留换行，不使用正文首行缩进 |
| JSON/XML 示例 | 代码块 | 内容较长时放入附录 |
| 超链接 | Word 超链接 | 显示文本应可理解，不只显示长 URL |
| 脚注 | Word 脚注 | 只有来源或补充说明确有需要时使用 |
| HTML 标签 | 按语义转换或转义 | 不把未识别标签直接显示在 Word 中 |

## 7. 项目标签和稳定编号映射

以下内容属于需求对象标识，转换时必须保持文本原样：

| Markdown 文本 | Word 表现 |
| --- | --- |
| `来源-001` | 普通正文或表格文本 |
| `页面-001` | 普通正文或表格文本 |
| `功能-001` | 普通正文或表格文本 |
| `字段-001` | 普通正文或表格文本 |
| `规则-001` | 普通正文或表格文本 |
| `业务状态-001` | 普通正文或表格文本 |
| `权限-001` | 普通正文或表格文本 |
| `异常-001` | 普通正文或表格文本 |
| `验收-001` | 普通正文或表格文本 |
| `待确认-001` | 普通正文或表格文本 |

Word 自动章节编号只作用于 `Heading 1` 至 `Heading 3`，不得重排或替换上述稳定编号。

## 8. 不支持直接等价转换的内容

| 内容 | 处理方式 |
| --- | --- |
| Markdown 原生不支持的复杂合并表格 | 使用结构化输入或专门 DOCX 组件生成 |
| Mermaid 源码 | 先渲染图片，再插入 Word |
| HTML/CSS 复杂布局 | 提取语义结构，重新使用 Word 样式排版 |
| 浮动卡片、网页阴影和交互控件 | 转为表格、图片或正文说明，不模拟网页交互 |
| SmartArt、宏和嵌入式对象 | 默认不生成；有明确交付要求时单独确认 |
| 动态目录、交叉引用和页码域 | 可写入域代码；在 Word 打开时更新并再次检查 |

## 9. 推荐生成流程

```text
Markdown PRD
    ↓ 读取封面元数据和章节结构
结构校验（标题、表格、稳定编号、占位符）
    ↓
套用某政务项目_PRD模板.docx
    ↓
映射 Word 样式、自动编号、表格和图片
    ↓
保存 DOCX
    ↓
检查文件可打开性、内容、样式、编号、表格和占位符
    ↓
按用户要求选择性转换 PDF 或抽查页面
    ↓
交付最终 DOCX
```

## 10. 转换后检查清单

- [ ] Markdown 文档标题已进入封面，没有被错误编号。
- [ ] Markdown `##` 至 `####` 与 Word 三级标题映射一致。
- [ ] Word 标题编号自动生成，Markdown 中的手工数字没有重复显示。
- [ ] 中文稳定编号原样保留。
- [ ] 所有表格完整、列宽合理并重复表头。
- [ ] 列表使用真实 Word 编号或项目符号。
- [ ] 图片和 Mermaid 渲染清晰，图题连续且可读。
- [ ] 代码块换行和空格未丢失。
- [ ] 封面和修订记录已填充，没有迁移历史业务内容。
- [ ] Word 与 Markdown 的需求内容、状态、权限和验收标准一致。
- [ ] 已完成 DOCX 结构、样式、编号、表格、图片关系和占位符检查。
