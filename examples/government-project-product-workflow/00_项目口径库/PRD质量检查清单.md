# 某政务项目 PRD 质量检查清单

> 使用方式：对每一项填写“通过 / 不通过 / 不适用”。标记“不适用”时必须在评审记录中写明原因；任一“必须”项不通过，PRD 不得进入“已确认”状态。

| 检查编号 | 检查维度 | 检查项 | 判断标准 | 是否必须 | 问题示例 | 修正建议 |

| 结构-001 | 文档结构 | 文档是否使用统一模板 | 章节顺序与 `PRD结构模板.md` 一致；未使用的条件章节标记“不适用”并说明原因 | 是 | 删除了固定章节，导致不同 PRD 无法横向对照 | 按模板补齐章节；不适用章节保留标题和原因 |
| 结构-002 | 文档结构 | 文档信息是否完整 | 文档名称、版本、状态、编写人、评审人、确认人和日期均有值 | 是 | 版本、责任人或更新时间为空 | 补齐文档信息后再发起评审 |
| 结构-003 | 文档结构 | 修订记录是否可追溯 | 每次修改均记录版本、日期、修改人、变更范围、来源和确认人 | 是 | 只写“优化内容”，未说明影响章节 | 写明受影响的页面、功能、字段、流程或状态 |
| 结构-004 | 文档结构 | 标题层级是否规范 | 正文标题不超过三级；使用 Markdown 标题和稳定编号；无仅靠加粗表示的章节 | 是 | 出现五级标题或“功能一”“其他”等模糊标题 | 重组章节并采用“对象 + 动作”命名 |

| 结构-007 | 文档结构 | 当前有效 PRD 是否使用中文稳定编号 | 标题使用“功能一”等中文序号；跨章节引用使用“功能-001”“字段-001”“验收-001”等中文编号；不存在英文编号前缀 | 是 | 当前 PRD 继续使用 `FUNC-001`、`FIELD-001`、`AC-001` | 按中文编号映射统一替换，并检查全部交叉引用 |
| 来源-001 | 来源分层 | 是否按文档类型区分内容性质 | 正式 PRD 按来源性质标记【事实】【推断】【建议】【待确认】或【历史资料】；反向补档 PRD 使用章节和表格结构区分，正文不得使用五类标签 | 是 | 将推测流程写成确定规则，或在反补 PRD 中逐条堆叠标签 | 正式 PRD 使用正确标签；反补 PRD 按页面现状、设计补充、差异说明、来源与依据和待确认问题分区 |
| 来源-002 | 来源分层 | 页面现状或已确认事实是否有来源 | 每条关键事实或页面现状可追溯到固定口径、已确认意见、会议纪要、正式文件、接口材料或已验证页面 | 是 | 写明具体规则，但没有任何来源编号 | 增加来源编号；无法确认时登记待确认问题 |
| 来源-003 | 来源分层 | 推断内容是否说明依据 | 推断内容明确写出由哪些页面、流程、字段或数据关系推导，不以确定语气表述；反补 PRD 在权限推断、差异说明等结构中记录依据 | 是 | 使用“系统必须”描述未经确认的推断 | 说明推断依据，并避免确定性措辞 |
| 来源-004 | 来源分层 | 设计补充是否与页面现状分开 | 优化目的和影响范围清晰，不覆盖已确认口径；反补 PRD 将目标方案放入设计补充或明确的目标方案列 | 是 | 将交互建议直接写成页面现状或既定业务规则 | 分离页面现状与设计补充，并说明影响范围 |
| 来源-005 | 来源分层 | 待确认事项是否集中登记 | 正式 PRD 的待确认内容引用 `待确认-xxx`；反向补档 PRD 的未决事项只在待确认问题表集中登记，正文需要关联时直接写“见待确认-xxx” | 是 | 正文多处散落“待确认”，末尾没有汇总 | 建立待确认编号和汇总表；反补 PRD 清除方括号标签及重复元描述 |
| 范围-001 | 范围管理 | 适用范围是否明确 | 明确端口、角色、功能、页面、流程起止和数据范围 | 是 | 只写模块名称，不清楚覆盖哪些页面和角色 | 按六个范围维度补充范围表 |
| 范围-002 | 范围管理 | 是否写明不做范围 | 存在“不做范围”章节；每项包含原因、承接方或后续处理、确认状态和来源 | 是 | 仅写“暂不考虑”，没有原因和后续处理 | 按 输出 编号补充结构化记录 |
| 范围-003 | 范围管理 | 是否与项目不做范围一致 | 逐条比对 `不做范围.md` 中适用于本模块的有效记录，PRD 未重新纳入对应能力 | 是 | 已明确外部系统承接的能力又出现在本期功能中 | 删除该能力或标记为范围冲突并重新确认 |
| 范围-004 | 范围管理 | 历史功能处置是否明确 | 引用旧系统能力时明确标记“继续办理 / 停用但保留查询 / 完全废弃 / 待确认”之一 | 条件适用 | 仅描述旧系统有该功能，未说明新系统处置 | 增加历史功能处置结论或 待确认 编号 |
| 页面-001 | 页面清单 | 页面清单是否覆盖全部页面形态 | 正文出现的列表页、详情页、表单页、工作台、弹窗和抽屉均在页面清单中有 页面 编号 | 是 | 功能说明出现编辑弹窗，但页面清单没有记录 | 补充页面清单并建立关联编号 |
| 页面-002 | 页面清单 | 页面入口和退出路径是否完整 | 每个页面均写明所属端口、进入方式、返回/关闭方式及必要的携带参数 | 是 | 只说明“进入详情”，未说明来源和返回路径 | 补充来源页面、目标页面、参数和返回结果 |
| 页面-003 | 页面清单 | 页面层级是否合理 | 独立任务和长表单使用二级页面；短流程使用弹窗；辅助查看或选择使用抽屉 | 是 | 列表、详情、长表单和全部配置平铺在一页 | 按任务关系拆分页面层级 |
| 页面-004 | 页面清单 | 页面结构是否完整 | 每个页面说明标题区、筛选区、主内容区、操作区和状态区；不适用区域说明原因 | 是 | 页面只描述主表格，没有标题、筛选和状态区 | 按页面结构表补齐 |
| 页面-005 | 页面清单 | 页面与原型是否一致 | 页面名称、层级、字段、按钮、弹窗、抽屉及跳转与当前有效 HTML 原型一致 | 是 | PRD 有“删除”按钮，原型不存在或名称不同 | 对齐 PRD 与原型，并记录差异处理 |
| 页面-006 | 页面清单 | 是否避免只用截图表达需求 | 截图仅用于辅助定位；页面规则、字段、操作、状态和异常均有可检索文字 | 是 | 正文写“页面如下图”，没有字段和交互说明 | 将截图内容结构化为表格和文字规则 |
