# 从会议纪要到测试验收

## 整理会议纪要

用 [`$meeting-minutes`](../../skills/meeting-minutes/SKILL.md) 整理逐字稿和评审意见。

1. 读取用户指定的会议笔记、转写或原始纪要，以及 `00_项目口径库` 中相关的现行口径。每条纪要保留可回查的位置，例如段落编号或时间戳。
2. 提取结论、不做范围、待确认事项和会后行动。明确确认的结论分配或复用 `来源-xxx`，记录影响的页面、角色、字段、权限、状态。意见冲突时保留各自依据，标为待确认。负责人或期限缺失时写「待指定」或「待定」。
3. 将确认结论整理为 PRD 需求来源表。用户要求更新 PRD 时，再写入对应章节，并核对受影响的原型、台账和验收标准。

示例：[模拟会议记录](01_原始资料/会议纪要/单位管理_模拟会议记录.md) → [结构化会议纪要](01_原始资料/会议纪要/单位管理_会议纪要.md) → [单位管理 PRD](03_PRD/PRD_单位管理.md)。

```text
使用 $meeting-minutes，整理“单位管理_模拟会议记录.md”，并附 PRD 需求来源表。
```

## 设计测试用例

用 [`$test-case-design`](../../skills/test-case-design/SKILL.md) 把验收标准展开为手工用例。

1. 读取当前 PRD 的验收标准，并用原型、字段字典、权限矩阵和状态流转表核对前置条件。按规则选择适用的正常、空态或边界、异常恢复和越权场景。
2. 每条用例记录测试编号、关联验收编号、优先级、测试数据和角色、操作步骤、可观察的预期结果、执行状态。一个验收标准可以关联多条用例。依赖未确认的阈值、角色边界或接口时，写明阻塞项，保留可以单独验证的部分。
3. 检查每条适用的验收标准都有用例或明确的覆盖缺口。新用例标为「未执行」。实际执行后记录环境、版本、结果与证据。发现差异时关联用例和受影响产物，修复后记录复测结果及同步范围，验证通过后关闭差异。

可复制[单位管理用例表](07_测试验收/功能测试点.csv)作为模板。查询、重置等可先在静态原型走查。服务端鉴权、接口失败恢复和落库核验需要具备对应能力的测试环境。

```text
使用 $test-case-design，根据“PRD_单位管理.md”设计手工测试用例，并列出验收覆盖、待确认项和联调依赖。
```
