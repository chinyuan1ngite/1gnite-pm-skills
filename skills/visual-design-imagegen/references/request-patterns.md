# Request Patterns

Read only the section matching the requested output. For a different raster composition, use the nearest pattern and keep the user's stated deliverable authoritative.

## UI concept

Build the brief from:

- product or page purpose;
- target users and primary task;
- required regions, states, and actions;
- exact labels or sample data that must appear;
- platform, canvas size, and aspect ratio;
- desired visual language and supplied references;
- elements that must be excluded.

Default to a front-facing complete UI canvas with familiar interaction patterns. Use device frames, browser chrome, perspective, or environmental mockups only when requested.

## Presentation infographic

Build the brief from:

- audience and viewing context;
- one central message;
- supporting facts, comparisons, sequence, architecture, or recommendations;
- required title, labels, and numbers;
- landscape, portrait, or another requested format;
- desired information density and visual tone.

Choose a composition that expresses the relationship in the content: overview, sequence, hierarchy, comparison, matrix, or layered architecture. Keep decoration subordinate to the message.

## Dashboard concept

Build the brief from:

- operational question and viewing distance;
- required metrics and their units;
- time range, geography, filters, and status semantics;
- central view and supporting analysis regions;
- supplied real values versus placeholders;
- normal, warning, and critical states;
- canvas ratio and installation context.

Then read [`data-dashboard-guidelines.md`](data-dashboard-guidelines.md). A concept image can communicate layout and visual hierarchy, but it cannot establish analytical correctness.

## Defaults

When the user leaves a presentation choice open:

- infer visual tone from the subject and audience;
- use 16:9 for desktop UI, meeting graphics, and dashboards, and 3:4 for mobile-oriented infographics;
- generate one direction;
- keep only the supplied title and essential short labels exact;
- use abstract or low-detail placeholders for missing secondary copy and data;
- treat the first reference image as the primary visual reference and later images as supporting references.

Do not use a default that conflicts with an explicit request.
