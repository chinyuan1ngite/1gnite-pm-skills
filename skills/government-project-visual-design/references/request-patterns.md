# 生图请求模式

## 一、高保真页面概念图

从用户请求中提取：

- 页面主题；
- 画布比例，默认 16:9；
- 使用场景；
- 必须出现的区域；
- 必须准确呈现的短文字；
- 允许自由发挥的区域；
- 禁止出现的内容；
- 参考图片及其用途，例如整体风格、配色、布局、组件质感或图表语言。

提示词应明确包含：正面平视的完整 UI 设计画布、无浏览器外框、无设备模型、非截图、现代政务专业 B 端风格，以及 `visual-guidelines.md` 中的色彩和禁止项。

调用示例：

```text
使用 $government-project-visual-design 生成一张高保真页面概念图。

页面主题：人才项目申报工作台
比例：16:9
必须出现：项目概览、申报进度、待处理事项、风险提醒
精确标题：某政务项目服务平台
视觉方向：现代政务、专业克制、中高信息密度
参考图：使用本次附图作为整体风格参考，只借鉴配色、布局节奏和组件质感
排除：参考图中的 Logo、品牌名称、业务文字和数据
不要读取项目 PRD 和 HTML 原型。
```

## 二、汇报图片

从用户请求中提取：

- 汇报主题；
- 阅读对象和使用场景；
- 核心结论；
- 指标、进展、问题、风险和下一步；
- 横版或竖版；
- 必须准确呈现的标题和数字。
- 参考图片及其用途，例如版式、信息层级、色彩或图表风格。

提示词应明确包含：清晰的信息层级、一个中心主题、克制装饰、易于会议或移动端阅读，以及不得补造业务数据。

用户未提供参考图时，根据内容结构从 `style-reference-catalog.md` 选择一张内置主参考图；只有确有必要时再增加一张辅助参考图。

调用示例：

```text
使用 $government-project-visual-design 生成一张项目进展汇报图。

比例：16:9
主题：本周产品设计进展
核心结论：完成需求框架、形成原型规范、待确认权限边界
下一步：补齐业务资料并启动模块级 PRD
参考图：未附图时由 Skill 从内置汇报图参考集中自动选择
不要补充未提供的数字和业务规则。
```

## 三、数据大屏概念图

从用户请求中提取：

- 大屏主题和使用场景；
- 画布比例，默认 16:9，超宽指挥屏可使用 32:9；
- 布局模式：中心指标、中心地图、多面板分析或流程监测；
- 核心指标名称；
- 中心主视图；
- 左右分析区和底部趋势区；
- 必须准确呈现的短标题和数字；
- 数据是真实值、用户提供的示例值还是纯视觉占位；
- 参考图片及其用途。

提示词必须遵守 `data-dashboard-guidelines.md`，明确包含：正面平视的完整大屏设计画布、无房间场景、无显示器外框、无观看人物、非截图、数据为视觉示意，以及不得补造业务统计。

调用示例：

```text
使用 $government-project-visual-design 生成一张数据大屏高保真概念图。

大屏主题：某政务项目人才服务运行态势
比例：16:9
布局模式：中心指标＋左右分析面板
核心区域：人才项目概览、申报趋势、区域分布、办理进度、风险提醒
数据口径：只显示模块名称，图表和数值均为视觉示意
不要使用内置汇报图参考集，不要补造正式统计数字。
```

## 四、信息不足时的默认处理

- 未给出比例：高保真页面使用 16:9；移动传播型汇报图使用 3:4，其余汇报图使用 16:9。
- 未给出视觉方向：使用现代政务、专业克制、中高信息密度。
- 未给出精确文案：只保留主题级短标题，其他文字使用低辨识度视觉占位。
- 未给出输出数量：生成一张，不主动扩展多个版本。
- 提供多张参考图但未说明用途：第一张作为主风格参考，其余图片只补充局部特征。
- 提到参考图但未实际提供：停止生图并请用户重新附加或提供可访问路径。
- 未提供参考图且任务为汇报图片：从内置参考集中选择最匹配的一张，不要求用户重复上传。
- 未提供参考图且任务为高保真页面概念图：使用文字视觉规范，不自动套用汇报图参考集。
- 未提供参考图且任务为数据大屏概念图：使用 `data-dashboard-guidelines.md`，不自动套用汇报图参考集。
- 数据大屏未给出布局模式：使用中心指标加左右分析面板。
- 数据大屏未提供精确数据：使用无刻度趋势形态、占位图表和弱化数值区域，不生成看似真实的随机数字。
